# 0028 — `micros` is a category-scoped namespace; microtypes are live pilot sites, and their data is agent-generated behind a provenance gate

- **Status:** Proposed
- **Date:** 2026-08-22 *(third draft — 2026-08-18 proposed a kind registry with
  pluggable ingestion adapters; 2026-08-19 dropped ingestion and the registry
  with it; 2026-08-22 restored the registry on a second real microtype and
  re-based templates on live pilot sites. The reversal is recorded in
  § Consequences rather than smoothed over.)*
- **Supersedes:** — (does **not** alter ADR-0013's stack axis; extends the
  ADR-0023 carve-out from ADR-0020's checks-over-verbs default; reuses the
  ADR-0023 engine and the ADR-0026 backend seam)

## Context

`sites/montereybayevents.com` went from `new bootstrap` to a deployed,
GSC-verified, 115-URL regional events calendar in nine phases over fifteen days
(v1.A–v1.I, 2026-08-03 → 2026-08-18). The operator wants that repeatable for any
city or region, and — since 2026-08-22 — for kinds of local site other than
events.

Read the pilot's cost honestly before deciding what a command can own. Roughly
**20%** was scaffold and architecture, **30%** was assembling the dataset, and
**~50%** was editorial judgement: an admission audit that found three "free"
listings charging $40–50, two events at the wrong venue, three phases of
incident-banner maintenance, one 598→1,733-word researched page. Only the first
two thirds are mechanizable.

lamill's CLI is **scope-first** since v7.A. The first design distributed this
work across `project` / `fleet` / `new`, which spent most of its risk on code
every one of the 50+ fleet sites runs through, and required adding a *vertical*
axis to `new bootstrap` — a second axis orthogonal to stack, sitting awkwardly
beside ADR-0013. The operator rejected that on 2026-08-18: these sites are **one
category**, and the work should not touch the others.

The dataset half was then reshaped twice, both times toward less machinery. Feed
ingestion — discovery, normalize, dedupe, propose/apply — was dropped, on the
observation that lamill already owns a supervised agent engine (ADR-0023/0026)
and that the pilot's own dataset was never ingested from feeds anyway: its ICS
pipeline was planned as v2 and never built, and the CSV that shipped 104 pages
was assembled by hand.

## Decision

**`micros` becomes a fifth top-level namespace scoped by *category* rather than
operational scope. A site declares membership with a single `microtype` scalar.
A microtype is defined by a live pilot site that `micros new` reads and adapts,
not by templates held in lamill. Datasets are generated by `project delegate`
under a provenance gate rather than ingested or hand-typed.**

- **(a) A category namespace is a deliberate deviation, and it has to be
  earned.** The rule: justified when a class of sites has **lifecycle verbs that
  would be meaningless on every other site in the fleet**. This rule exists to
  stop `micros` becoming a precedent for a namespace per site-type.

- **(b) The boundary runs in both directions, and both halves bind.** Micros
  verbs never touch a non-micros site. **But micros sites remain ordinary fleet
  members** — `fleet check`, `fleet fix`, `CHECK_150` and the universal catalog
  still cover them, and `project delegate` still operates on them, which (f)
  depends on. Micros is a layer on top, not a carve-out from underneath.

- **(c) Membership is a top-level scalar, not a table.** `microtype = "events"`
  beside `schema`. Presence is the membership test; the value selects the
  microtype. Additive-optional per **ADR-0017**, and **non-micros never carry the
  field** — a contract with seven clauses: the parser returns `None` on absence
  and never raises; no check warns because it is missing; absence *is* the
  membership answer, so micros verbs decline cleanly rather than reporting a
  gap; `micros list` shows only sites that set it; **no fleetwide backfill,
  ever** (unlike `[stack]`, which was universal-but-undeclared and correctly got
  a v27.C backfill — `microtype` is a genuine minority and most of the fleet
  should never carry it); a baseline test loads a minimal file and exercises
  every consumer; and `schema` stays `lamill-toml-v1`.

  Named `microtype` rather than `microsite_type` because `[content].site_type`
  already exists in these files, and two similar keys a few lines apart — one a
  content descriptor, one a tooling switch — is a scanning hazard. Unrecognised
  values are rejected at *use*, not at parse, so a typo cannot make the file
  unparseable and break `project check` for an unrelated reason. Note the TOML
  constraint: bare keys after a table header bind to that table, so `microtype`
  must be written in the preamble and needs its own byte-preserving upsert path
  rather than `lamill_toml_edit.set_table` (ADR-0018).

- **(d) Three verbs.** `micros new <domain>`, `micros list`, `micros health
  <domain>`. **Named `health`, not `check`** — `project check` already runs the
  universal catalog against the same domain, and two `check`s with different
  meanings on one site is an ambiguity the operator resolves every time they read
  a command. `status` was likewise avoided: v7.A retired it when `project status`
  became `project check`.

- **(e) A microtype is a live pilot site plus a policy record.** `micros new`
  reads `sites/<pilot>/` **at run time** and copies-then-adapts, reusing the
  existing `--git-url` pipeline (`_clone_to_genai` → `_copy_from_genai` → a
  Claude-subprocess adaptation modelled on `port_to_astro`) with a local sibling
  as source and *region* rather than *stack* as what gets adapted. New sites
  therefore inherit the pilot's current thinking, not a snapshot.

  This makes the registry far lighter than the frozen-template version. Row
  schema, page templates and schema.org builders **live in the pilot site and
  lamill never holds them.** A registry entry carries only: which pilot to read;
  an adaptation profile (substitutions + strip list); a staleness check; and a
  generation profile. It is a registry of **pointers and policies, not
  implementations**.

  A **pilot-health gate** runs first — clean tree, build passes, `project check`
  clean — and refuses otherwise, mirroring delegate's dirty-tree refusal.

- **(f) The dataset is agent-generated; no ingestion pipeline, no generation
  verb.** `project delegate` becomes micros-aware off `microtype`, gaining a
  doctrine profile and the gate in (g), reusing `delegate.py`'s sandbox,
  two-axis supervisor, resume-on-cap, adaptive split and `DelegateBackend` seam
  rather than building a second engine. Consequently **`--pull` / `--propose` /
  `--apply` do not exist**: the review surface is the **git diff of the CSV**,
  which the operator already reads before committing.

- **(g) The provenance gate — a fourth verify link, micros runs only.** This
  exists because of an inversion. Delegate generates *code*, where a wrong answer
  breaks the build: loud, mechanical, catchable, which is why its three-link gate
  works. **Data generation inverts this — a hallucinated event builds green,
  passes every check, renders correctly, and ships a wrong date to someone
  deciding when to show up.** The pilot proved no mechanical gate catches that.

  Correctness therefore cannot be asserted, but **sourcing can be, and
  mechanically**. Every generated row carries a source URL **fetched during the
  run** (not recalled), with the claim locatable in that fetched text. Fields not
  locatable — a time, a price, an address — come back tagged unconfirmed rather
  than filled, per (h). An unresolvable source fails the gate.

  **The gate does not catch a source that is itself wrong**, and that is stated
  rather than hidden: the pilot's v1.I page exists because aggregators were
  confidently carrying prior-year dates and the most findable shuttle timetable
  was from 2010. Price, address and time stay human-audited when load-bearing.

- **(h) The provenance doctrine is a category standard**, injected as generation
  guardrails and carried by every pilot: `confidence: official | derived |
  unpublished`; the `Admission` union; `timesConfidence`, whose unconfirmed
  values are shown to the reader but kept out of the JSON-LD because structured
  data is quoted stripped of its qualifiers; clock times never synthesised; no
  `offers` without sourced admission; `streetAddress` never derived from a venue
  name. Underneath all of them: **a page does not have to make a claim it cannot
  stand behind — it can make a different, true claim about the public record
  instead.**

- **(i) `micros health`'s checks are a micros-scoped bundle** (ADR-0005
  machinery), not universal-catalog entries — they would be `n/a` on 50
  unrelated sites. Staleness is **per microtype**: horizon for events,
  re-verification age for services.

- **(j) Two microtypes are in scope for v47:** `events`, generalized from the
  existing pilot, and `services` (local services / utilities), which requires a
  pilot to be **built first** — there is nothing to read otherwise. That phase is
  site work inside a tool tier, and is named as such rather than hidden.

**Reconciliation with ADR-0020.** ADR-0020 placed post-publish indexing in the
conformance/fix loop because it was *conformance-shaped*: a detectable gap, an
assertable green. Micros' verbs are **lifecycle-shaped** — scaffolding a site
that does not exist yet — where there is neither. Same carve-out **ADR-0023**
made for `project delegate`, whose engine (f) reuses. The default is preserved
where it applies: staleness *is* conformance-shaped and ships as checks per (i).
Generation adds no verb at all.

**Status is `Proposed`.** The namespace, boundary, `microtype` scalar, verb
names, generation-over-ingestion posture, live-pilot templates and the gate's
existence are locked. Open: gate strictness (fail the run vs drop the row),
staleness thresholds per microtype, the services vertical and domain, and whether
the adaptation pass is a plain subprocess or a full delegate run. Flips to
`Accepted` when v47.A closes those.

## Consequences

- **Shared-surface blast radius is two files.** One namespace registration in
  `cli.py`, one scalar in `lamill_toml.py`. `bootstrap.py`'s CLI surface and
  signature are untouched; `delegate.py` gains a profile and a gate behind a
  `microtype` guard.
- **The pilot sites become load-bearing infrastructure.** This is the real cost
  of (e), accepted knowingly on 2026-08-22: `montereybayevents.com` can no longer
  be experimented on freely, because a mid-refactor state would propagate into
  every new site. The pilot-health gate contains it but does not remove it.
  Adding a microtype now means *build one good site of that kind, then point
  `micros` at it* — which is a real constraint on how fast microtypes can appear.
- **The registry was cut and restored, and the record should show why.** The
  2026-08-18 draft proposed a `MicroKind` protocol with pluggable adapters
  designed from a single example. Dropping ingestion removed three of its five
  slots, leaving a one-entry dict, so it was cut on 2026-08-19 as
  over-architecture. The operator then named a second genuinely different
  microtype — local services — which passes the exact test used to justify the
  seam originally: **horizon is events-only**; a business listing has no horizon
  and goes stale differently. The restored registry is not the one that was cut:
  live-read moved the implementations into the pilots, so it carries pointers and
  policies instead.
- **The one-example risk is materially reduced but not gone.** Two microtypes
  that differ on the time axis is a far better basis than one. But services
  generalizes from a single deliberate build while events generalizes from nine
  phases of real use, so the services half of the seam is the weaker half until
  it has been used.
- **lamill's agent surface widens from code to facts.** ADR-0023 moved lamill
  toward agent-orchestrated site *development*; this moves it toward
  agent-generated site *content*. The provenance gate is the entire reason that
  is defensible: without it, lamill would publish unfalsifiable claims to live
  sites at fleet scale.
- **False-green risk carries over from delegate.** BUG-064 reported
  `✓ agent finished · $0.00` on a run that created nothing, because stream-EOF
  was treated as success. The data analogue: *"the model returned 40 rows"* must
  never be the success signal — rows are the cheapest thing an LLM produces.
  v37.E's baseline gate has a direct analogue too: probe sources before
  generating, since the pilot hit `fire.ca.gov` 403-ing automated reads and
  BigSurKate answering one day and 403-ing the next.
- **The `write-lamill-seo-page` skill is deliberately overridden** on `[VERIFY]`
  + `noindex`; recorded here rather than left as a per-site note. `noindex` on a
  live earning page costs more than that skill accounts for (pilot v1.D,
  reaffirmed v1.G).
- **Cross-repo consequence.** `sites/montereybayevents.com/docs/prd.md`'s
  v2.B–v2.E phases plan a local ingestion build and are moot — neither lamill nor
  the site is building feed ingestion. Its "where does the pipeline live?"
  question is answered (nowhere; generation replaced it) and its no-auto-publish
  decision survives as the never-auto-commit stop in (f). That site also becomes
  a template source, which its own docs should say.
- **`micros survey` is deferred, not dropped.** The supply audit is real work the
  operator will do by hand for the first few regions; the v2.A method is
  documented and the phase is written.
- **The scope promise is bounded, on purpose.** Micros reaches the pilot's v1.B
  state — dated, located, schema-valid, sourced listings — not its v1.D/v1.I
  state. Editorial depth stays human and `project delegate` work. Stated here to
  stop a later reading of "one command builds montereybayevents" that the code
  cannot honour.
